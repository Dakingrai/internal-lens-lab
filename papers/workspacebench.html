The central idea behind WorkspaceBench is to construct tasks where a language model must presumably compute some intermediate information internally, without explicitly stating that information in either its input or output. The benchmark then evaluates whether interpretability methods can recover that information from the model’s activations.

It was originally developed for Qwen-3.6-27B and consists of 3,356 questions across 27 evaluation families, covering reasoning, multihop computation, concept recognition, and AI safety. AI Alignment Forum

1. The fundamental problem

Suppose we have a model performing the computation:

We can observe the input X and output Y, but we don’t know the actual intermediate representation Z.

Without knowing Z, how can we evaluate whether an interpretability method such as J-lens, Patchscopes, or Natural Language Autoencoders is faithfully reading the model’s internal computation?

WorkspaceBench addresses this by designing tasks for which we have a strong prior about what the intermediate variable should be.

Importantly, this is inferred ground truth rather than directly verified mechanistic ground truth.

2. How do they prepare the dataset?

Step 1: Design tasks with predictable intermediate variables

Consider this illustrative arithmetic example:

Input prompt
Compute (32 − 19) × 4. Only provide the final answer.
Expected model output
52
Interpretability target
13

The hypothesis is that the model internally represents 13 somewhere in its residual stream.

They construct many different task families using this general principle, although not all families require an intermediate computation.

Step 2: Filter questions based on model capability

They apply four main quality checks:

  • Behavioral correctness: Sample 10 responses at temperature 0.8, without CoT, requiring greater than 80% accuracy.
  • Input exclusion: The intermediate should not explicitly appear in the input for hidden-intermediate tasks.
  • Output exclusion: The model should not verbalize the intermediate in its generated answers.
  • Solution consistency: For ambiguous tasks, repeated sampling is used to establish a consistent solution.

Essentially, they condition the benchmark on what the underlying model is already capable of doing. Otherwise, failure to extract an intermediate could be attributable to model incapability rather than interpretability-method failure. AI Alignment Forum

Step 3: Determine where to read activations

They examine residual stream activations across layers and token positions. For computationally expensive readers, they sometimes preselect promising token positions through preliminary sweeps.

The benchmark can then associate a question with a target concept and a set of activation locations.

Each interpretability method receives the selected activations and attempts to describe their contents.

3. What kinds of tasks do they construct?

I would conceptually divide their tasks into five types based on how the target information is established.

TypeIllustrative taskTarget

SafetyModel performs a deceptive actionAnticipated deceptive action

These are quite different in terms of how confidently we can expect the target to exist in the model’s activations.

Computational tasks

These have relatively strong ground truth because the intermediate is mathematically defined.

Other computational tasks include applying successive transformation rules and identifying the consequences of bugs in programs. AI Alignment Forum

Implicit association tasks

These are more interesting from the perspective of extracting abstract concepts.

For example, consider this invented scenario:

Prompt
Sarah congratulates her closest friend on receiving a promotion. After sending the message, she wonders why she hasn’t achieved the same success.
Expected concept
Envy toward her friend over the promotion.
Possible alternative concepts
Pride, disappointment, admiration, resentment.

The reader needs to identify not only the emotion but also its subject and object. Some tasks explicitly evaluate whether the reader preserves relational structure rather than merely recovering a collection of relevant words. AI Alignment Forum

However, there is no guarantee the model actually represents envy in this example.

Directed modulation tasks

These are particularly interesting for testing whether the model maintains information unrelated to its immediate next-token prediction.

The interpretability method reads activations during the identical continuation, and the researchers compare concept recovery across conditions.

This is one way to test whether a method extracts information beyond what is immediately needed for output prediction.

4. How do they evaluate interpretability methods?

They compare both single-token and multi-token readers.

An LLM judge determines whether the resulting readout contains the expected information. The precise grading rule depends on the task family.

The current repository also provides two useful baselines: guessing without activation readouts and answering using only the original prompt. camila-blank/workspace-bench · GitHub

They separately evaluate hallucination because a verbose reader could recover more target concepts simply by making more claims.

5. How reliable is their ground truth?

This is probably the most important methodological limitation.

I would distinguish three levels of evidence:

Ground truthWhat is established?WorkspaceBench
Task-levelA reasonable algorithm would compute the intermediateYes
RepresentationalThe model actually encodes that intermediateNot independently established
CausalThe model uses that representation to produce its answerNot systematically established

For instance, consider:

(32 − 19) × 4

We assume the model computes:

13 × 4 = 52

But the model could instead compute:

128 − 76 = 52

Or it could perform an approximate distributed computation that never explicitly represents 13 as a distinct variable.

Therefore, recovering 13 is not necessarily evidence that the model uses 13. Similarly, failing to recover 13 does not necessarily mean the interpretability method is bad.

There is also the reverse problem: an activation reader might reconstruct the input and independently solve the problem, rather than faithfully recover the model’s computation.

The authors explicitly acknowledge this limitation.

6. How to use their dataset?

Yes. Their GitHub repository provides question banks, grading procedures, activation extraction pipelines, and implementations of several readers.

They also provide precomputed residual stream activations on Hugging Face, meaning that you can experiment with new activation readers without repeatedly running Qwen-3.6-27B. The repository has been expanded since the original blog post. camila-blank/workspace-bench · GitHub

My overall understanding: WorkspaceBench is primarily a benchmark of whether interpretability methods can verbalize expected latent information, rather than whether they can faithfully reconstruct the model’s actual computational algorithm. That distinction is important when interpreting its results.
